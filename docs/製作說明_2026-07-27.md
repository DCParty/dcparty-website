## 一、本次最重要的發現

### Google 認知的 dcfilms.tv 是「DCParty」，不是 DC Films

網站的根 layout 從未從 DCParty 專案的範本改過來，導致對外宣告的實體資訊全錯：

```
siteName            = "DCParty"
siteTitle           = "DCParty — AI 訂閱制數位服務"
description         = "一個月費，無限數位需求。網頁、軟體、設計、音樂…"
keywords            = 訂閱制, 數位服務, 網頁設計, 軟體開發, UI/UX, 音樂製作
Organization schema = name: "DCParty"
WebSite schema      = name: "DCParty"
每頁標題後綴         = "| DCParty"
```

**這極可能是 SE Ranking 報告（7/07–7/20）全部關鍵字 0% 曝光、平均排名 100 的主因。**
Google 把這個網域歸類成「一家做訂閱制數位服務的公司」，自然不會拿它去比對「商業攝影」「形象影片」這類查詢。

已全部修正為 DC Films，並補上完整營業資訊。

### 三個主要頁面被 canonical 標籤擋在索引之外

`layout.tsx` 設有一行全域 canonical：

```js
alternates: { canonical: baseUrl },
```

在 Next.js App Router 中，此設定會被**所有未自行覆寫的頁面繼承**，
導致以下三頁對 Google 宣告「本頁的正式版本是首頁」：

| 頁面 | 原本宣告的 canonical |
|---|---|
| `/projects` | `https://dcfilms.tv` |
| `/about` | `https://dcfilms.tv` |
| `/contact` | `https://dcfilms.tv` |

Google 據此判定為重複內容而跳過索引，即 Search Console 回報的
**「替代網頁（有適當的標準標記）」**。

受影響的都是**入口頁**：`/projects` 為作品集總覽、`/contact` 為詢價頁。
使用者搜到個別作品後，Google 無法將其導向作品集或聯絡頁。

83 個作品內頁未受影響（`projects/[slug]/page.tsx` 本就有自訂 canonical），
`/services` 亦無此問題（該頁重寫時已一併宣告）。

**修正**：移除全域設定，改由各頁宣告相對路徑，交由 `metadataBase` 解析。

| 頁面 | 修正後 |
|---|---|
| `/` | `https://dcfilms.tv` |
| `/projects` | `https://dcfilms.tv/projects` |
| `/about` | `https://dcfilms.tv/about` |
| `/contact` | `https://dcfilms.tv/contact` |
| `/services` | `https://dcfilms.tv/services` |
| 83 個作品頁 | 各自指向自身 |

已於 `layout.tsx` 留下註解說明成因，避免日後再被加回。
全 sitemap 88 筆網址複查，canonical 不一致頁數為 **0**。

### 作品內頁的 Notion 內文從未被渲染

`getProjectBySlug()` 有回傳 `markdown`（關於此案／Idea／Process／Credit），
但 `projects/[slug]/page.tsx` **完全沒有使用它**。git 歷史顯示渲染區塊
在 commit `06d33bd`（perf: 圖片優化 + ScrollReveal 加速）被誤刪。

另外 `@tailwindcss/typography` 從未安裝，全站 `prose` 類別都是空操作。

**修正**：安裝 typography 外掛並於 `globals.css` 啟用；還原渲染區塊，
並將原本的 `prose-invert`（深色專用）改為 `prose-stone dark:prose-invert`，
使亮暗雙主題皆可讀。

**影響範圍**：83 筆作品中只有 **11 筆** Notion 頁面有內文，其餘 72 筆本來就是空的。
此修正讓那 11 筆完整顯示；72 筆仍只有一段描述，屬資料缺口，非程式問題。

### 20 個作品頁在線上是 404

Notion 放行新作品後，`/projects` 列表顯示 84 個連結，但其中 20 個點進去是 404。

成因是兩層快取疊加：
1. 上次 build 時 `generateStaticParams()` 只取得 60 個 slug
2. 新路徑雖會即時渲染，但資料層 `revalidate = 3600` 仍快取著舊的 60 筆
3. `getProjectBySlug()` 找不到資料 → `notFound()` → **Vercel 將此 404 快取**

已透過重新部署解決（重跑 `generateStaticParams` 並清除快取）。

- 舊的 `google.com/ping?sitemap=` 端點 **已於 2023 年停用**（實測回 404）。
  sitemap 自動發現改由 `robots.txt` 的 `Sitemap:` 宣告負責，本站已具備。

## 七、預期時程

修正實體訊號（DCParty → DC Films）後，Google 需要重新爬取與重新歸類：

| 時間 | 預期現象 |
|---|---|
| 第 1 個月 | 排名數字可能仍為 0，但 Search Console 的曝光數應先有變化 |
| 第 2–3 個月 | 第一層長尾字開始進入前 50 |
| 第 4–6 個月 | 第一層進入前 20，第二層開始出現 |

第三層的頭部字（形象影片、商業攝影等）建議僅作趨勢觀察，不列入 KPI，
以免每月看到 0% 而誤判 SEO 無效。
